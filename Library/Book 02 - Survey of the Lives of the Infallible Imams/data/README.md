# Data

- `chunks.json` = 160 source-understanding chunks.
- `meta.json` = source inventory and extraction status.
- `study_book02.json` = structured pedagogical layer: concepts, terms/topics, key phrases, and cross-unit connections. It does **not** embed questions -- those live only in `../exam_bank/questions.json`, which `study.html` fetches separately and merges in at load time. Keeping the question bank in exactly one file is deliberate: two earlier copies (this file, and one hardcoded inside an exam_bank HTML tool) had already drifted out of sync with each other before this was cleaned up.

**Known gap 1: `claim_examples` is not genuine content yet.** Each unit also carries a `claim_examples` array (claim/reasoning/evidence/lesson, one per concept) that the framework calls for as a real, distinct pedagogical layer. In this book it isn't one: `reasoning` duplicates the matching concept's `explanation` verbatim in all 160 entries, `evidence` is either the same duplicate or a truncated prefix of it in all 160, and `lesson` is the identical boilerplate sentence in all 160 ("Preserve the source's exact distinction and connect evidence back to the claim."). The field is left in the file rather than deleted, so a future pass can populate it with genuine, distinct reasoning/evidence/lesson content per concept without a schema change; until that happens, don't build a new view on top of `claim_examples` assuming it holds real content.

**Known gap 2: `concepts[].explanation` is the source passage, not a distillation of it.** Checked across all 160 concepts: `explanation` is byte-for-byte identical to the text of the chunk named in `source_chunk_id`. (The note above used to say the learning hub showed "only concepts" *because* that layer was the genuinely distilled one -- that assumption was wrong; it hadn't actually been checked against the raw chunk text until this was caught.) This isn't necessarily bad as source material — a concept card showing a real passage verbatim is legitimate — but it means `explanation` cannot be treated as a short summary distinct from the source, and a view must not show both `explanation` and the matching chunk from `chunks.json` as if they were two different things. The learning hub now renders each concept as its title plus one single collapsible reveal of the passage, not a visible "explanation" paragraph followed by a separate "source passage" reveal of the same text.

Keep source extraction separate from pedagogical rendering. Do not invent missing source content. Before trusting any field as "the distilled version" of something, actually diff it against the raw chunk text rather than assuming the field name describes its content.
